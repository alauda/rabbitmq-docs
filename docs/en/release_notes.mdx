## v4.3.3

### New and Optimized Features

#### Product Renamed

- The product is now named **Alauda Data Services Message Broker E1** (formerly Alauda Streaming Service for RabbitMQ). Technical identifiers are unchanged: the CRD group `rabbitmq.com`, the `RabbitmqCluster` kind, the package name, and image paths. Existing instances need no changes.

#### Platform Compatibility

- The same v4.3.3 plugin is released for ACP 4.1, 4.2, 4.3, and 4.4.
- Supported RabbitMQ versions: 3.12, 4.2, and 4.3.

#### Unsupported Versions Are Reported

- If `spec.version` names a RabbitMQ version this release does not ship, the operator no longer silently runs the default image. It sets the `ReconcileSuccess` condition to `False` with reason `UnsupportedRabbitmqVersion`, emits a Warning event with the same reason, and leaves the instance unchanged until `spec.version` is corrected.

### Fixed Issues

- Fixed the default user password change not taking effect after updating the default user Secret. This behavior was lost in v4.3.1.
- Fixed TLS certificates not being provisioned automatically for instances with TLS enabled. This behavior was lost in v4.3.1.
- The operator now uses `Lease` objects for leader election.
- Fixed high-severity security vulnerabilities in the operator, broker, and exporter images by updating the Alpine base image (OpenSSL), the Go toolchain (1.26.6 for the operator), and Go dependency modules.

## v4.3.1

### New and Optimized Features

#### RabbitMQ 4.3 Support

- Added RabbitMQ 4.3 as a selectable version for new instances.
- Changed the default version for newly created instances to RabbitMQ 4.2.
- Kept RabbitMQ 3.12 compatibility for existing workloads.

#### Operator Baseline Upgrade

- Rebased the operator on upstream RabbitMQ Cluster Operator v2.21.0.

## v4.2.1

### New and Optimized Features

#### RabbitMQ 4.2 Upgrade Capability

Introduced a complete 3.12.x to 4.2.x upgrade path, including:

- Planned downtime migration (drain and migrate).
- Zero-downtime blue-green migration based on Federation.

#### RabbitMQ Exporter Integration

Added opt-in standalone exporter support for per-cluster metrics.

- Enable or disable exporter resources with `spec.exporter.enabled`.
- Automatically manage `Deployment`, `Service`, and `ServiceMonitor` as `<cluster>-exporter`.
- Support `spec.exporter.image` override and Prometheus scraping on `/metrics` (port `9419`).

### Compatibility Changes

- RabbitMQ 3.8.16 is no longer supported in v4.2.x.

## v4.1.0

### New and Optimized Features

Improved stability and fixed several security issues.

## v4.0.0

### New and Optimized Features

#### Component-Platform Decoupling

Alauda Streaming Services for RabbitMQ's lifecycle has been decoupled from platform's, which means when customer needs a certain feature or a bug fix, RabbitMQ team can release immediately instead of waiting for the platform release together.

#### Real-Time Logs on Component Details Page

The logs on RabbitMQ details page have been replaced with real-time logs that update instantly, facilitating troubleshooting and issue analysis.

#### New Version Support

Alauda Streaming Service for RabbitMQ now supports RabbitMQ server v3.12.14.
